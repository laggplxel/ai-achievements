If you want to continue being skeptical because you don't understand the math here (which you obviously don't), I can give you a little math lesson right here right now on verifying one of AI's achievements.

This one is easy and short to verify yourself in case you're skeptical.

Claude Fable 5 (something publicly accessible to you today btw, so don't go on about "it's a research specialized model") disproved the Jacobian conjecture (that all polynominal multivariable functions with a constant non zero Jacobian determinant are injective) with a counterexample ( https://en.wikipedia.org/wiki/Jacobian_conjecture#Counterexample_for_n_%3E_2 ):

  • a = (1 + xy)³ z + y² (1 + xy)(4 + 3xy)
  • b = y + 3x(1 + xy)² z + 3xy²(4 + 3xy)
  • c = 2x - 3x²y - x³z

If you calculate the Jacobian determinant of this, which you can verify with a regular calculator, https://www.wolframalpha.com/input?i=Det%5BD%5B%7B%281%2Bx+y%29%5E3+z+%2B+y%5E2+%281+%2B+x+y%29+%284+%2B+3x+y%29%2C+y+%2B+3x+%281+%2B+x+y%29%5E2+z+%2B+3x+y%5E2+%284+%2B+3x+y%29%2C+2x+-+3x%5E2+y+-+x%5E3+z%7D%2C+%7B%7Bx%2Cy%2Cz%7D%7D%5D%5D

It shows -2. So it qualifies. It's constant, and it's not zero.

Now the counterexample happens in the fact the map sends three distinct inputs, (0, 0, -1/4), (1, -3/2, 13/2), and (-1, 3/2, 13/2) to same identical output vector (-1/4, 0, 0).

So it's not injective. Because injective means to be one to one and have a distinct output for each input. But this one has the same output for three different input.

Hence the Jacobian conjecture is false for n=>3. It is simple to verify.

The exposition of how this counter example works is more complex, though: https://arxiv.org/abs/2608.00222

Part two: “Computers always did math!”

The entire point is that the LLM is not connected to any proof checker which works like Z3 (atp, automated theorem prover) nor Lean.

What you are saying is comparing it to systems such as Z3, when it just isn’t.

The important idea here is that despite no proof checker to formally check its thought process throughout, it has output a correct and novel idea to solve a problem that was later checked and verified by several mathematicians.

There is no logical verifier module in the transformer architecture.

This is also in no way similar to other computer checked problems like the four color theorem because 4CT was literally just a very exhaustive case check, and mathematicians were deeply unsatisfied with it because it offered no logical arguments or proofs.

This literally does give the logical arguments and proofs. New ones, which seem to be correct.

It combined two ideas, primitive sets in number theory linked with Markov chains / hitting probabilities on the divisibility poset, to solve the problem. It gave a logical argument in natural language that was correct.

That is literally what human mathematicians do.

For example, Andrew Wiles solves Fermat's Last Theorem, a very great problem that had been unsolved for 350 years: https://youtu.be/i0UTeQfnzfM?t=155

He did it by noticing a link between two concepts people haven’t done before, which is Kolyvagin-Flach method + Iwasawa theory.

Like GPT here, he connected two ideas.

“Brute force” by definition needs something to force against. What’s being forced against? Considering there’s no proof checker, nor an exhaustive case check like 4CT.

If it’s “brute forcing” without a proof checker, it is impossible to generate a coherent proof, let alone in just 80 minutes, because mathematics is infinite. It’ll just constantly spew gibberish.
